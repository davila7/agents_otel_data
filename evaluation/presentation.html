Empirical benchmark · read APIs · July 27, 2026 · rev 2 — all four platforms tested live

Which agent-observability platform gives your data back?

Four platforms ingested identical traces from the same instrumented agents — a raw Anthropic call, a tool-calling agent, and an MCP agent. Then we turned around and tried to get every byte back out through each platform's read API, scoring only what live responses proved. Documented-but-untested capabilities earned nothing.

How the benchmark ran

Phase 1

Research

Two independent sweeps — industry evaluation practice and OTel GenAI semantic conventions — synthesized into a 9-criterion rubric with weights summing to 100.

Phase 2

Executable tests

One standalone Python script per platform (evaluation/eval_*.py) exercising the live read API: completeness checklist, filters, aggregation, pagination, formats, latency, write-to-read lag.

Phase 3

Adversarial verify

A separate agent re-ran every script from scratch, curl-checked sampled claims, and hunted for fabricated metrics. All four results reproduced; one best-case outlier corrected (Logfire ingest lag 1.6 s → 5.0 s).

Phase 4

Judge panel

Three judges — data-engineer, platform-operator, AI-engineer lenses — scored the same evidence independently; near-unanimous agreement, no split over one point.

Scoring rule: for each platform and criterion, judge scores (0–10) are averaged, then the weighted total is Σ weight × avg / 10. Capabilities that exist in docs but were not demonstrated live were capped — the benchmark measures what an engineer actually gets today, from code, with ordinary credentials. Rev 2 re-ran the full pipeline after a read-scope API key for Logfire became available; the other platforms' tests were replayed from the verified rev 1 evidence.

Platform detail

Logfire

What the tests proved

  • Arbitrary SQL over raw spans (records table): expressions, aggregations, windowing — the most powerful query surface of the field, all demonstrated live.
  • Only platform returning gen_ai.* semantic conventions verbatim: input/output messages, tool call args and results, usage, W3C trace IDs.
  • Four export formats actually received: JSON, NDJSON, CSV, Arrow.

Where it lost points

  • Returns Arrow binary unless you send Accept: application/json explicitly — docs say JSON is the default.
  • Strict 422 on missing min_timestamp; rate limits undocumented.

What the tests proved

  • BTQL free query language live: attribute filters and grouped aggregations, curl-verified.
  • Fastest ingest of the field (0.4 s write-to-read) and tight, stable latency.

Caveats — read before quoting

  1. Credentials decide benchmarks. In rev 1 Logfire scored 6.67 — dead last — because only a write token existed and its query API correctly rejected it. One read-scope API key later it leads the field at 96.40. The evidence-only rule cuts both ways.
  2. Export formats: Logfire is the only platform that honored content negotiation; Braintrust, LangSmith and Langfuse all returned JSON regardless of Accept headers. LangSmith's Parquet bulk export exists but is plan-gated and untested by rule.
  3. OTel fidelity is rare: only Logfire surfaced gen_ai.* semantic conventions verbatim on the read path; the other three reshape telemetry into proprietary schemas.
  4. Judge panels have noise: re-scoring the identical rev 1 evidence moved other platforms' totals by up to ±2 points (e.g. Braintrust 90.57 → 89.40). Differences smaller than that are not meaningful; the ordering was stable within each panel.
  5. Latency shared one network but not one moment; Langfuse and LangSmith showed run-to-run variance up to ~1.8 s, Braintrust and Logfire were tight and stable.
