# CLAUDE.md

Guidance for Claude Code when working in this repository.

## What this repo is

An AI-agent observability benchmark: the same three traced scenarios are written into four OTEL-based platforms (Logfire, Braintrust, LangSmith, Langfuse), then each platform's **read API** is benchmarked with executable scripts and scored by a judge panel. `README.md` has the verdict; `evaluation/RESULTS.md` has the full methodology and caveats.

## Layout and conventions

- `logfire/`, `braintrust/`, `langsmith/`, `langfuse/` — self-contained `uv` projects, each with the same three demos: `01_messages.py` (direct Anthropic call), `02_tools.py` (Pydantic AI agent + tools), `03_mcp.py` (Pydantic AI + `mcp-server-time` over stdio).
- `evaluation/` — one `eval_<platform>.py` per read API, `rubric.md` (9 weighted criteria, weights sum to 100), `RESULTS.md`, `results/*.json` (raw evidence), `rescore_continuous.py` (sensitivity check), `presentation.html` (self-contained report).
- All docs and deliverables in **English**.
- `cryptography` is pinned `<45` in every folder: newer versions need a rust toolchain to build on Intel macOS. Avoid adding `temporalio` (no Intel-macOS wheels).

## Running things

```bash
# demos
cd <platform> && uv sync && set -a && source .env && set +a
uv run 01_messages.py

# benchmark (each eval sources its platform's .env)
cd evaluation
set -a && source ../logfire/.env && set +a
uv run --with requests python eval_logfire.py   # writes results/logfire.json

# sensitivity re-scoring (pure recompute, no API calls)
python3 rescore_continuous.py                   # writes results/final_scores_continuous.json
```

## Credentials — critical rules

- All secrets live in per-folder `.env` files, **gitignored**. Never commit keys, never print secret values from scripts (mask if needed).
- Logfire: the real project is **davila7/ant-agent**. `logfire/.logfire/logfire_credentials.json` is stale (points to a deleted `starter-project`) — do not trust it. Read access requires a **pylf_v2 API key with read scope** (`LOGFIRE_READ_TOKEN` in `logfire/.env`); write tokens are rejected by the query API. The `logfire read-tokens create` CLI subcommand is broken (AttributeError).
- Braintrust: project `agents-otel-data`, id `5d169ed6-af7e-4dbd-a8ca-458253acbfe8`. Traces appear in that project, not "My Project".
- Credentials decide benchmarks: the first eval run scored Logfire 6.67/100 purely because the wrong credential type was provisioned.

## Read-API gotchas (verified live, July 2026)

- **Logfire** `POST https://logfire-us.pydantic.dev/v2/query`: returns **Arrow binary by default** despite docs — always send `Accept: application/json`. `min_timestamp` is required (422 otherwise). Rate limit ~10 queries/min. Management API: `https://api-us.pydantic.dev/api/v1/`.
- **LangSmith** `POST /api/v2/runs/query` and `POST /api/v2/traces/query`: auth via `X-Api-Key` and `X-Tenant-Id`; projects addressed by UUID (resolve names and tenant IDs via the current `GET /api/v1/sessions?name=...` tracer-sessions endpoint); filter DSL like `eq(status, "error")`; cursor pagination via `next_cursor`; rate limit 300 req/10 s.
- **Braintrust** `GET /v1/project_logs/{id}/fetch` + `POST /btql`: Bearer auth; fetch pagination can re-return rows — dedupe by `id`.
- **Langfuse** `GET /api/public/v2/observations` (preferred since Aug 2026; v1 `/api/public/traces` is deprecated): HTTP Basic (pk-lf / sk-lf); cursor pagination via `meta.cursor`; selective field groups via `?fields=` (I/O needs explicit opt-in); rows are observations — group by `traceId` to reconstruct traces. Real-time ingest with recent SDKs (measured 10.7 s lag, down from 46.5 s on v1).
- **mcp-server-time** requires `--with 'mcp<2'` in the uvx invocation (imports `McpError`, removed in mcp 2.x) — already pinned in all four `03_mcp.py`.

## Scoring architecture — keep these invariants

- `results/final_scores.json` is the frozen judge-panel output (banded rubric). **Never edit it**; sensitivity analyses live alongside it (`final_scores_continuous.json`), regenerated by `rescore_continuous.py`.
- July raw evidence (`results/{platform}.json`) is frozen too. Re-runs go to new files: `results/*_aug2026.json` + `results/langfuse_v2.json` (August same-session cohort, scored via `rescore_continuous.py --cohort aug2026`). If a vendor ships improvements, re-run **all four** evals back-to-back — rubric rule 2 forbids mixing sessions in one cohort.
- `rescore_continuous.py` re-scores only latency and freshness (log-scale, cohort min-max, lower is better); the other 7 criteria keep judge averages. Full-precision arithmetic, rounding **only at display** — intermediate rounding caused ±0.01 drift once.
- Latency methodology: 3 timed identical calls per platform, median, timer wraps the full HTTP round trip (`perf_counter`/`monotonic`), 429s retried outside the timed window. Known asymmetry: `eval_logfire.py` uses bare `requests.post` (no `Session`), slightly penalizing Logfire.
- Honest-framing rule (learned via adversarial review): the ranking (Logfire > Braintrust > LangSmith > Langfuse) is robust across scoring schemes, but the Logfire–Braintrust **gap is method-dependent (~2–7 points)** — never claim "effectively tied" or cite undocumented noise margins. Logfire freshness is n=1; cohort normalization depends on cohort membership (dropping Langfuse flips the continuous top spot).
- Every number in RESULTS.md/README must trace to a value in `results/*.json` — no doc-only claims.
