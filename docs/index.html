Which agent-observability platform gives your data back?

Raw measurements

Latency = median of 3 timed identical read calls, full HTTP round trip. Freshness = seconds from span emission until it is queryable via the read API. Green marks the best value in the cohort.

The four read APIs

Logfire
POST /v2/query · SQL · pylf_v2 read token

Strength: full SQL over spans, and the widest export menu (JSON, NDJSON, CSV, Arrow).

Friction: returns Arrow binary unless you send Accept: application/json; min_timestamp is required; ~10 queries/min rate limit.

Braintrust
GET /v1/project_logs/{id}/fetch · POST /btql · Bearer

Strength: BTQL query language and sub-second freshness (0.4 s in both cohorts).

Friction: JSON-only export; fetch pagination can re-return rows — dedupe by id.

LangSmith
POST /api/v1/runs/query · X-Api-Key

Strength: expressive filter DSL (eq(is_root, true)) and solid cursor pagination.

Friction: projects addressed by UUID (resolve names first); 10 req/10 s rate limit; Parquet export is plan-gated; slowest read latency in the August cohort.

Langfuse
GET /api/public/v2/observations · HTTP Basic pk/sk

Strength: biggest jump July → August (65.63 → 80.83 continuous) after moving to the observations v2 API; fastest read latency in the August cohort (202.5 ms).

Friction: rows are observations — group by traceId to reconstruct traces; I/O fields need explicit ?fields= opt-in; slowest ingest freshness in the August cohort (10.7 s).

Read the numbers honestly

  • The ranking is robust; the top gap is not. Logfire > Braintrust holds across every scoring scheme tried, but the size of the gap is method-dependent (roughly 2–7 points depending on banded vs continuous scoring). Don't read the August 0.37-point margin as a precise measurement.
  • Continuous scores are cohort-normalized. Latency and freshness use log-scale min–max within the cohort, so the worst platform gets 0.0 by construction. LangSmith's latency 0.0 means "slowest of these four in this session", not "broken".
  • Logfire freshness is a single sample (n=1 per cohort). Treat its freshness score as indicative, not measured.
  • July is the frozen record. The judge-panel scores (96.40 / 89.40 / 80.93 / 72.03) were produced once by a 3-judge panel with a banded rubric and are never edited. August is a re-run on the same rubric after Langfuse shipped its v2 API — all four platforms were re-measured back-to-back in one session.
  • Small data, single session per cohort. Three traces per platform, one benchmark session per cohort. This measures API ergonomics and behavior, not production-scale performance.
  • Credentials decide benchmarks. In the first run Logfire scored 6.67/100 purely because the wrong credential type was provisioned. Every score here was re-verified with working read credentials.
Reproduce it: evaluation/eval_<platform>.py writes results/<platform>.json; rescore_continuous.py recomputes the continuous cohort scores. Rubric, methodology and caveats: evaluation/RESULTS.md.
